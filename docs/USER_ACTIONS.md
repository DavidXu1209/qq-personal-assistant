# 需要你操作的步骤

这些步骤可以等你远程操作方便时再做。代码修改、接口配置和离线检查由 Codex 完成。

## 1. QQ 小号登录

- 服务启动入口：项目根目录的 `01-start.cmd`。
- 登录页面入口：项目根目录的 `02-qq-login.cmd`。
- 手机 QQ 切换到配置中的机器人小号，扫描网页登录页中的二维码并确认。
- 使用自己的主号发送消息。不要在机器人登录页选择主号。
- 登录后，从主号给小号私聊发：`请总结：本周要完成 Java 集合练习。`
- 能收到摘要才代表真实 QQ 收发已接通。配置文件存在、接口启动和离线测试通过，都不能替代这一步。

## 2. iCloud 日历授权

- 在 [Apple 账户](https://account.apple.com/) 的“登录和安全 → App 专用密码”生成一个密码，标签可填“QQ提醒”。这要求 Apple 账户已开启双重认证：[Apple 官方说明](https://support.apple.com/zh-cn/102654)。
- 双击项目根目录的 `03-icloud-setup.cmd`，按终端提示依次填写 Apple 账户和刚生成的专用密码；密码隐藏输入，每项填完按回车。
- 专用密码只填本机窗口，不要发到聊天。凭据使用当前 Windows 用户的 DPAPI 加密保存。
- 保存后网关会自动重启加载凭据，已运行的 QQ 登录程序不会因此重启。
- 日历列表中已有“QQ提醒”时使用它；没有时首次保存事项会尝试创建。

## 3. 最后确认一次实际效果

- 从主号给小号发：`测试日程：15 分钟后参加测试会议，持续 30 分钟。`
- 查看回复中的实际保存结果，随后在 iPhone 日历中确认“QQ提醒”日历及测试会议。
- 明确开始时间的 QQ 提醒提前 10 分钟，所以这条测试大约在发出后 5 分钟提醒；以回复显示的时间为准。
- 只有日期的事项默认当天 09:00 提醒。
- 如果 iCloud 尚未授权，QQ 提醒仍可保存，回复会明确说明日历写入失败；这条事项不会自动补写进 iCloud。

## 已知限制

- QQ 实时收发需要电脑开机、联网，QQ 桥和网关都在运行；锁屏可以，睡眠或关机不可以。
- 已保存的逾期提醒会在下次启动补发；断网重试或发送瞬间崩溃可能造成少量重复提醒。
- 未交给网关的离线 QQ 消息不能保证追回。
- X 链接若遇到登录墙或读取失败，请转发正文或截图；机器人不能凭链接猜帖子内容。
- 合并转发当前每个转发读取首批最多 40 条，长内容会限量读取，不保证覆盖整段历史。
- 当前不主动监控 X，不使用付费 API。摘要会消耗现有 Codex 订阅额度。

## 提醒管理和故障状态

登录后，主号可以直接给小号发以下命令，不消耗模型额度：

- `查看提醒`：查看当前提醒及编号。
- `查看提醒 全部`：包含已提醒和已取消的事项。
- `取消提醒 abcdef12`：把示例编号替换成列表中显示的编号。QQ 提醒先取消，再尝试删除机器人对应的 iCloud 日程；如果日历删除失败，手机原日程可能仍会提醒。
- `修改提醒 abcdef12 2026-10-09 14:00`：修改开始时间并保留原持续时长，QQ 提前 10 分钟提醒。只填日期则当天 09:00 提醒。修改已取消的编号会重新启用该提醒。
- `状态`：查看 QQ 连接、处理开关、最近模型错误、待发提醒和日历同步失败。状态查询不调用模型，不查询订阅剩余额度。

这些命令只处理主号直接发送的内容；引用和合并转发中的命令不会执行。若 QQ 无法回复，可在电脑双击根目录 `04-status.cmd` 查看状态。

相同的标题、开始时间和地点会识别为重复通知，保留已有提醒编号；修改后重复转发旧通知不会把时间改回去。不同措辞的标题或不同地点不保证识别为同一事项。超过 50 条时列表只显示前 50 条。
