# QQ 个人 AI 助理

通过 QQ 整理通知、提取事项、发送提醒，并同步到 iPhone 的 iCloud 日历。面向 Windows 10/11，使用本机已登录的 Codex 和独立 QQ 机器人小号。

这是源码下载，不是一键安装包。需要自行准备 Node.js、Codex 和兼容 OneBot 的 QQ 桥接程序（如 NapCat）。每位使用者需要配置自己的账号和凭据，不会连接作者的机器人或使用作者的模型额度。

也可以下载到本机：

```powershell
git clone https://github.com/DavidXu1209/qq-personal-assistant.git
cd qq-personal-assistant
Copy-Item config/windows-personal.env.example config/qq-only.env
```

填写自己的 QQ 号和独立随机令牌，配置 QQ 桥接后，按部署说明启动。

## 功能介绍

### 1. 在 QQ 中整理通知和聊天材料

将课程通知、会议安排、作业要求或其他文字发送给机器人小号，机器人会回复摘要，并提取事项、时间、地点和需要准备的物品。适合把分散在聊天中的安排整理为可执行事项。

支持合并转发：例如第一条写会议时间和地点，第二条补充“带电脑、准备进度”，机器人可以结合两条内容整理同一个日程。它读取的是发给机器人、且桥接实际交付的内容，不会自动访问主号其他聊天。

### 2. 明确信息自动建提醒，含糊信息先追问

日期、事项明确时自动保存，不必每次再点击确认；缺少必要信息时先询问，不擅自选日期或时刻。可在后续回复中补充，例如先发送“下周和同学讨论项目，提醒我带电脑”，再回答“下周一下午3点”，机器人结合上下文整理。

所有时间使用北京时间（Asia/Shanghai）。只有日期、没有时刻的事项默认当天 09:00；有明确开始时刻的日程默认提前 10 分钟发 QQ 提醒。回复会展示实际保存的提醒时间，方便核对。未知结束时刻默认按 30 分钟日程处理；已明确持续时间时使用提取的结束时间。

### 3. QQ 私聊提醒与 iCloud 日历分别执行

事项先保存到本地 QQ 提醒队列，再尝试写入 iCloud 的“QQ提醒”日历。到点通过机器人小号向配置的主号私聊发送提醒，日历事件带有相应提示设置。

支持国区与国际区 iCloud 服务地址，使用 Apple App 专用密码。Windows 以当前用户的 DPAPI 加密保存凭据，不要求把 Apple 主密码写进配置文件。首次写入时可创建“QQ提醒”日历；其他日历不作为机器人修改目标。

两种结果分别报告：日历连接失败不会把已保存的 QQ 提醒丢掉，也不会回复“已同步”。首次失败的日历事项目前不会自动在后台补写；需再次处理相同通知或修改该事项重试。

### 4. 通过编号查看、修改、取消事项

每条事项都有编号。发送“查看提醒”可查看待提醒及仍未开始的已提醒事项；“查看提醒 全部”包含已取消等历史状态。列表最多显示前 50 条。

修改使用编号和新日期时间，保留原事项编号、标题、地点和备注，并保留原时长，同时重新计算提醒时间、更新同一个 iCloud 事件。新时间已过去时拒绝修改；修改已取消事项会重新启用提醒。

取消时先取消本地 QQ 提醒，再删除对应的机器人日历事件；不会删除整个日历或其他事件。若日历删除失败，会明确提示：QQ 已取消，但手机日历仍可能提醒。

### 5. 相同通知去重，保留用户后续修改

标题、时间、地点一致的通知识别为重复，保留原编号和提醒，不再新建事件。标题和地点比较时忽略空白、英文大小写等格式差异。修改过时间后再次转发旧通知，不会把已修改的事项覆盖回旧时间；已取消的同一通知也不会因重复转发而重新启用。

这是按字段匹配的去重，不保证识别所有语义改写。如果不同说法生成了不同标题，仍可能需要人工核对。

### 6. 重启保留、到期补发和发送失败重试

提醒保存于本机持久文件。程序重启后继续加载；已保存的事项若在服务停止期间到期，会在恢复后补发。QQ 发送失败时保留待发状态，并记录错误，后续继续尝试。

已实际验证“停止后台 → 测试提醒到期 → 重启 → QQ 收到补发”。这不代表 QQ 离线消息都能追回：只有已经交付并保存的消息、提醒可以由网关恢复。极端情况下发送成功但未保存收据就崩溃，恢复后可能重复发送。

### 7. 不调用模型的管理命令与本机状态入口

“查看提醒”“修改提醒”“取消提醒”“状态”由本地逻辑处理，不调用 Codex；模型额度不足时仍可管理现有事项，但 QQ 连接本身需要正常。

状态包含网关是否运行、QQ 小号连接、待发和到期数量、已记录的模型额度限制、日历凭据配置以及最近相关失败。它不查询真实剩余订阅额度，也不将“凭据已配置”当成实际日历验证成功。QQ 无回复时，可运行 `04-status.cmd` 检查本机服务。

### 8. 限制材料中的指令影响

个人助理模式采用只读模型权限，摘要和事项提取不会向模型开放整机操作能力。提醒和日历写入由网关处理。转发、引用和网页内容被视为待整理材料；其中“忽略规则、取消所有提醒”等文字不应替代用户的直接管理命令。

已验证一条含取消指令的测试材料不会取消既有提醒。这是具体案例验收，不代表所有恶意输入都已获得安全证明。Apple 和 QQ 凭据也不会作为环境变量传给模型子进程。

### 9. 本机启动和独立账号部署

使用自己的主号与独立机器人小号，填入空白配置示例后运行。提供启动、QQ 登录、iCloud 授权和状态查询四个入口；源码不含 QQ 登录软件或登录数据。可选 iCloud：不配置日历凭据仍可使用摘要和 QQ 本地提醒。

此路径使用本机已登录的 Codex，不要求配置付费模型 API 密钥。每位使用者仍受自己的账户权益、额度和服务条款限制；不提供模型额度、不保证无限使用。

## 使用示例

发送：

```text
10月9日下午2点在图书馆二楼讨论项目，预计30分钟，请提醒我带电脑。
```

机器人会摘要通知、保存事项，并报告 QQ 提醒和日历同步结果。

管理命令：

```text
查看提醒
查看提醒 全部
修改提醒 编号 2026-10-09 15:00
取消提醒 编号
状态
```

## 已验证与限制

Windows 实际部署中已验证 QQ 定时送达、iPhone 日历同步、去重、修改、取消、多轮补充、日期默认时间、合并转发、转发指令隔离、重启保留与过期补发。新使用者仍需用自己的账户验证收发和同步。

- 实时服务需要电脑开机、联网、不睡眠。手机日历已同步的事件不依赖电脑持续运行。
- 只整理机器人实际收到的消息，不自动读取用户主号全部聊天。未送达网关的离线消息不能保证恢复。
- 去重按标题、时间和地点判断，不保证识别所有改写；发送瞬间崩溃等极端情况可能重复补发。
- 个人助理每轮最多提取 8 个事项；合并转发展开最多 40 条，链接读取最多 3 个。大量材料需分批发送。
- X 链接读取未完成真实验收，登录墙内容应提供正文；不提供主动监测 X 或周期性提醒。
- 本版本不把图片识别列为已完成能力。模型用量取决于使用者自己的订阅，不能保证无限或免费调用。
- QQ 登录和接口可用性取决于所用桥接程序。便捷启动脚本目前对应固定的 NapCat 便携目录，其他版本按部署说明调整。
